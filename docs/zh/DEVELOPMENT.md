## 保持不变的实现选择

引擎采用平衡空间叶块、轴对齐下界和编译实现的平方距离计算。搜索按 `(平方距离, 原始行号)` 排列候选，并保留边界等距点。调试过程中保留冻结目标和贡献边界。以下修复没有引入搜索引擎性能调优，也没有修改目标。

持久化与 CLI 校验受到特别关注，因为格式错误的文件应通过清晰、受支持的错误路径退出。校验和本身不能验证索引几何不变量，文件扩展名也不能保证加载器返回对象的类型。这些发现补全工程边界，没有改变搜索算法。

## 检查发现的问题

| 发现 | 为什么重要 | 此检查点的修改或状态 |
| --- | --- | --- |
| 元数据中的 `sha256` 可能为 null、列表或字符串；错误值进入字典操作后触发 `AttributeError`。 | 错误清单绕过了预期的校验报错路径。 | 增加显式字典类型检查和必需键集合校验，并为错误形式添加回归用例。 |
| JSON `true` 被接受为 `format_version: 1`。 | Python 中 `bool` 是 `int` 的子类，且与 1 比较相等；仅判断相等不足以约束格式。 | 要求格式版本具有真正的整数类型。 |
| CLI 的无效数值参数触发 argparse 消息，但缺少中文文本。 | 普通用户错误绕过了双语报错契约。 | 增加 `BilingualParser.error` 处理和回归覆盖。 |
| Mypy 无法推断所需的数组形状和 mmap 属性类型。 | 运行行为与静态契约的表达不一致。 | 增加显式形状与 mmap 相关类型注解；属于类型修复，不是性能修改。 |
| 初始依赖锁选择了比声明的构建后端更新的 setuptools/wheel 组合。 | 成功解析依赖锁，不代表干净安装会使用声明的构建工具链。 | 增加精确开发依赖固定值，与 `setuptools==80.9.0` 和 `wheel==0.45.1` 对齐。干净安装验收仍须单独验证。 |
| 第二轮审计发现空 NPY 输入触发 `EOFError`。 | 普通文件错误处理尚不完整。 | 编写此检查点时，修复与回归验证正在进行。 |
| 第二轮审计发现伪装为 `.npy` 文件的 NPZ 压缩包，导致非预期加载对象、句柄生命周期问题与 `AttributeError`。 | CLI 假设 `np.load` 必定返回 ndarray。 | 此检查点中，数组类型校验、资源处理和回归验证正在进行。 |

依赖锁问题说明，“解析依赖”与“复现安装”需要分别检查：运行依赖集合与构建后端都必须符合记录配置。同样，搜索测试通过并不代表覆盖了所有错误输入路径。

### 记录更正

提交 `6b73052` 的正文提前写成了 **112 项测试**。原工作环境实际完成的测试集报告是 **111 项通过，耗时 6.91 秒**。保留原提交，不重写历史；此处更正数量。不会虚构额外测试或额外成功运行来补齐差异。

首次记录此更正时，单独启动的干净 `.venv` 全量测试仍在进行。随后该运行完成，结果为 **111 项通过，耗时 30.77 秒**，已在上表单独记录。两个实际运行都不支持提交正文中 112 的数量。

上面的每个测试耗时各自属于一次本地运行，不是搜索引擎性能测量。增加回归用例时，测试数量可能上升；数量不能替代对实际覆盖用例的理解。

## 发布前文档验证

最终文档和生成结果就绪后，运行 `python scripts/check_docs.py`。[检查器](../../scripts/check_docs.py) 验证文档文件名配对、必需的根目录语言配对、代码围栏闭合和相对文件链接目标；不验证语义翻译一致性、章节锚点或远程网页，这些需要人工审阅。本段记录验证过程，不表示已观察到该检查通过。

对照实现和原始证据审阅成对的[架构契约](ARCHITECTURE.md)、[使用导览](WALKTHROUGH.md)、[研究依据](RESEARCH.md)与[实验结果](RESULTS.md)。导览可执行代码块已经按上文记录完成检查。最终结果应对照未更改的[实验协议](PROTOCOL.md)，保留不利场景，并在发布验收材料中明确列出跳过的检查。

## 证据边界

[冻结协议](PROTOCOL.md) 约束实验目标和计时。原始基准证据与生成的[实验结果](RESULTS.md) 回答性能问题；本记录回答做了什么，以及过程中哪些检查失败。本地测试、静态检查、包安装、容器运行和远程 CI 是不同验收活动。不能因为其中一项成功，就把待完成或不可用的另一项写成通过。

后续验证应作为已观察的检查点追加，同时保留早期发现及其当时状态。计时后修改引擎，必须重新运行受影响实验并更新源码指纹。不要为了适配测量结果而重写初始目标。
