[English](../en/EXPERIMENTS.md) · [冻结协议](PROTOCOL.md) · [自动生成的完整表格](RESULTS.md)

## 机器与测量条件

主机为 Apple M1 Pro、arm64、10 个逻辑 CPU、16 GiB 物理内存，Darwin 内核 25.6.0。使用 Python 3.12.2、BoundScout 0.1.0、NumPy 2.2.6、SciPy 1.15.3、threadpoolctl 3.6.0 和 h5py 3.13.0。[environment.json](../../results/environment.json) 保存去除私人信息的环境记录。

基准通过 `threadpool_limits(1)` 和 `cKDTree.query(workers=1)` 请求单原生线程。原始线程池清单为空，因此没有记录到可控制的原生线程池。主机为共享交互式环境，观察到另一个无关进程持续占用 CPU。没有 CPU 亲和性绑定、主机独占、温控、能耗测量或设备同步的保证。全部计算使用 CPU；没有测量 GPU 或容器性能。

每种方法独立构建，先执行构建后的一个查询，再进行一次完整预热。随后完成七次完整查询批次测量，每轮按固定种子随机排列六种方法。墙钟计时使用 `perf_counter`；每次计时结束后检查正确性，校验本身位于计时区间之外。数据准备、构建、存取、正确性检查和独立 RSS 子进程均不计入稳态查询延迟。存取时间与首次查询时间各为一次观察，并非七次重复的分布。没有主动清空缓存：“首次查询”不代表冷缓存或应用启动。

共享主机的波动仍然可见。例如 `clustered-large-k`/20260922 的有效 cdist-256 样本范围是 17.986–203.780 ms，中位数为 19.150 ms。七个样本全部保留。随机方法顺序可以减轻固定顺序偏差，无法消除资源竞争。七次重复支持描述性的中位数和范围，不支持 p99、置信区间或统计显著性结论。两个种子分别报告。

[原始协议](PROTOCOL.md) 和 [full.json 配置](../../configs/full.json) 均在性能计时之前冻结。主要目标始终为：**相对 cdist-256 的批次中位耗时至少加速 1.50 倍，同时向量计算量至少减少 75%**。看到结果后没有修改目标。完整矩阵均使用 64 个独立查询、float64、叶大小 256，以及种子 20260921 和 20260922。

| clustered-primary | 32,768 | 32 | 10 | 合成数据，16 个高斯簇 |

簇数据的中心标准差为 8，簇内噪声标准差为 0.5。训练与查询的簇标签和噪声基于相同中心独立采样。这些有利的合成输入与真实嵌入数据有明确区别。冻结矩阵同时改变了维数与 k，并非能单独隔离每个参数影响的完整因子实验。

GloVe 来自 [ANN-Benchmarks](https://ann-benchmarks.com/glove-25-angular.hdf5)，原始预训练向量的许可见 [NOTICE](../../NOTICE_zh.md)。下载文件大小为 127,359,688 字节，SHA256 为 `51004cb0ae962159f0db507a51fec2b395de14b166f55976c89f16bd2f8b6391`，含 1,183,514 个训练向量和 10,000 个测试向量，每个向量 25 维。这是本地实际观察到的文件摘要，不代表上游发布过该校验值。原始数据记录完整的采样训练/测试行号、种子、归一化选择、源文件摘要和准备后的数组摘要。返回的本地 ID 指向采样训练子集；`train_rows` 将其映射回源文件行号。

向量先以 float64 做 L2 归一化，再计算平方欧氏距离。由于候选集合改变，没有复用上游完整语料的邻居标签。数据获取发生在基准之前，没有报告下载延迟。真实数据准备包含校验、读取、采样与归一化，两个种子分别耗时 253.141 和 117.271 ms，均排除在查询延迟之外。向量不进入 Git；发布内容仅包含来源与测量证据。

## 方法、资源与公平性

| 方法 | 计时内容 | 用途与资源差异 |
|---|---|---|
| cdist-256 | SciPy 编译平方距离核、批次计算与保持平局规则的部分 top-k | 预注册的实用穷举基线，每块 256 个训练向量 |
| cdist-4096 | 相同基线，每块 4,096 个训练向量 | 本次更强的穷举对照，披露 Python 小块循环开销 |
| ckdtree | SciPy 精确 `query`，`eps=0`、`workers=1`，再将欧氏距离平方 | 已有编译空间索引；`leafsize=256`（SciPy 默认值为 16），没有调参扫描 |
| spatial-pruned | 空间打包与保守边界盒下界的 BoundIndex | 本项目可审阅机制；记录实际向量计算量和访问块数 |
| spatial-unpruned | 相同空间布局算法，设置 `prune=False` | 关闭下界计算与剪枝；独立构建以测量首次查询 |
| input-pruned | 原始输入顺序分块，开启剪枝的 BoundIndex | 检查缺少空间打包时仅靠剪枝是否有效 |

所有方法对相同数据与查询批次返回相同数量 k 的结果，均包含查询合法性检查。独立基准不会在每次查询时重复校验整个训练矩阵；索引的数据校验计入构建时间。它与包内通用 `exhaustive_search` API 不同，后者每次调用都会校验数据库。不能把基准中的数字表述为该公共 API 的计时。

cdist 基线借用准备好的输入，同时处理 64 个查询。块大小 256 的距离矩阵为 128 KiB，块大小 4096 时为 2 MiB；合并候选距离和 ID 还需额外内存。核心逐个处理查询，每个 256 行叶块的距离向量为 2 KiB，另有全部块下界、排序和 top-k 工作区。BoundIndex 拥有打包数据副本，原输入仍存活。1 GiB 的逻辑索引限制与 64 MiB 的默认输出限制不是整个进程的内存上限。没有施加操作系统 RSS 硬限制，cKDTree 完整逻辑分配统计不可用。没有树叶大小扫描、两种配置以外的穷举块大小扫描，也没有 BLAS/GPU 精确检索对照。

在 `clustered-primary` 上，空间剪枝每批次计算 152,576 和 152,320 个向量，而穷举需要 2,097,152 个，减少比例分别为 92.7246% 和 92.7368%。空间剪枝中位耗时为 11.195 和 11.288 ms，cdist-256 为 91.535 和 92.389 ms，cdist-4096 为 40.504 和 39.464 ms。主要结果中的 8.18 倍依赖预注册的小块基线；3.50–3.62 倍是本次更保守的穷举比较。cKDTree 仅需 5.570 和 4.160 ms，BoundScout 相对这一精确索引慢 2.01 和 2.71 倍。

小规模簇数据虽然减少了 88.87–89.94% 的向量计算，相对 cdist-4096 只获得 1.08–1.16 倍加速。下界计算与 Python 候选维护可能消耗大部分节省。大 k 簇数据相对 cdist-4096 保持 1.58–1.59 倍加速。由于矩阵不是完整因子设计，不能据此建立 k、N 与加速比的一般关系。

## 消融与不利场景

在两个主要工作负载种子上，关闭剪枝后耗时 124.901 和 131.174 ms，计算全部向量；保留剪枝但按输入顺序分块后耗时 129.859 和 132.390 ms，也计算全部向量。空间打包并剪枝仅需 11.195 和 11.288 ms。因此，对这些簇输入，打包后的有效几何结构和实际跳过的距离工作均不可缺少。未剪枝路径比两个 cdist 基线都慢，也说明 Python 逐查询/逐块管理有显著成本。此消融未单独隔离缓存局部性：遍历次序、下界工作与剪枝会共同变化。

四个 128 维各向同性组合均**没有剪掉任何向量**。空间剪枝相对 cdist-4096 慢 2.14–2.42 倍。在 N=32,768 时，空间剪枝耗时 210.032 和 214.641 ms，大块穷举为 97.975 和 98.486 ms。cKDTree 在这里更慢，为 463.059 和 520.249 ms；因此，仅凭超过该树就声称整体性能优势会产生误导。

真实 GloVe 两个组合仅减少 2.2827% 和 1.2329% 的向量计算。空间剪枝耗时 120.734 和 122.022 ms，相对 cdist-4096 的 36.001 和 36.710 ms，分别**慢 3.35 和 3.32 倍**。cKDTree 耗时 30.725 和 26.826 ms。第二个种子开启剪枝甚至比关闭后更慢：122.022 对 119.302 ms。观察与“边界盒重叠使下界较弱”的解释相符，但尚未独立测量各因素的因果贡献。当前实现不会在几何结构不利时自动切换为平坦穷举。

## 构建、存储、内存与回本

主要工作负载的空间剪枝准备开销：

| 种子 | 构建 ms | 首个单查询 µs | 保存 ms | 加载 ms | 逻辑索引 MiB | 独立峰值 RSS MiB |
|---|---:|---:|---:|---:|---:|---:|
| 20260921 | 46.511 | 1593.5 | 12.583 | 22.505 | 8.313 | 122.547 |
| 20260922 | 40.650 | 356.1 | 11.745 | 32.359 | 8.313 | 128.484 |

每个主要打包索引的逻辑数组占用为 8,717,320 字节，持久化文件总大小为 8,718,535 字节。RSS 测量的是从模块导入开始，经过数据准备、构建和一个查询批次的新进程峰值。它包含数据准备阶段的临时峰值，无法单独隔离持久索引开销。两个主要种子的 cdist-256 峰值为 90.422/91.000 MiB，cdist-4096 为 126.859/118.297 MiB，cKDTree 为 88.812/89.359 MiB，空间剪枝为 122.547/128.484 MiB。这些单次子进程观察不能与逻辑字节数相减，也不是受控的分配差值。

当分母为正时，按实测构建成本与批次中位耗时差计算：`ceil(build_seconds / (baseline_median_seconds - spatial_median_seconds))`。两个主要种子相对 cdist-256 均在**一个含 64 次查询的批次**后回本，相对 cdist-4096 均需**两个批次**。估算排除了存取、获取和准备，并假设之后的查询分布与计时条件相近。相对主要场景中更快的 cKDTree，没有查询耗时回本。对于这次各向同性和真实 GloVe 结果，相对任一穷举基线都不存在有限的构建摊销回本点。

## 正确性、局限与后续实验

全部 72 个方法/工作负载/种子记录通过完整批次距离检查，容差为 `rtol=1e-12, atol=1e-12`，包含每次计时重复的输出。本矩阵中全部 BoundIndex 与 cdist 输出的有序 ID 和距离都与参考完全相同。所有方法的最大距离差为 `2.8421709430404007e-13`，来自 cKDTree 的欧氏距离平方比较。cKDTree 的等距 ID 顺序不是验收要求。36 次 BoundIndex 存储往返与 72 次独立 RSS 测量全部成功。这些是已测输入的观察，不是对所有可表示浮点输入的排序证明。

证据支持一种适用范围较窄的几何优化，并包含明确的真实数据负结果。它不证明新的近邻算法、对已有索引的整体优势、生产延迟、服务系统收益或其他机器上的结果。坐标轴方向、查询分布、叶大小、更大 k 和高维边界盒重叠仍是重要限制。旋转测试、叶大小扫描、经实测的自适应平坦回退、更大真实数据集，以及受控主机上的重复实验，均为后续问题，而不是已经完成的能力。
